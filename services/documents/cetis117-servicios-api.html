CETIS 117 - Servicios REST de Asistencia

Documentación funcional del backend Spring Boot para ESP32 + GM60 + Firestore

Versión backend: v5 Base Firestore: zona-d Puerto local: 8080 Formato: JSON / multipart

Servicios incluidos

  • Registrar entrada o salida por huella
  • Crear autorización de salida
  • Importar alumnos desde CSV
  • Consultar alumno e historial
  • Limpiar registros antiguos
POST /api/asistencia/registrar

Registrar entrada o salida por huella

Este es el servicio principal que consumirá el ESP32 después de que el lector GM60 identifique una huella. El ESP32 solo envía el fingerprintId. El backend decide automáticamente si corresponde registrar una entrada, una salida normal, una salida autorizada o si el alumno requiere autorización para poder salir.

Lógica

SituaciónResultado
No existe registro del alumno para el día actualSe crea EntradaRegistrada
Ya existe entrada y todavía no llega la ventana permitida de salidaBusca autorización por alumno y luego por grupo
No existe autorizaciónDevuelve Requiere autorización de salida
Existe autorizaciónRegistra SalidaAutorizada y guarda el idAutorizacion
La hora actual es igual o mayor a horaSalida - minutosToleranciaSalidaRegistra SalidaRegistrada
Ya existen entrada y salidaNo crea otro registro

Request

{
  "fingerprintId": 1
}

Response - entrada registrada

{
  "resultado": "ENTRADA_REGISTRADA",
  "mensaje": "Registro de entrada exitoso, bienvenido",
  "estado": "EntradaRegistrada",
  "idRegistro": "1_2026-10-04",
  "idAutorizacion": null,
  "nombreAlumno": "Manuel Damian Guinto Méndez"
}

Response - requiere autorización

{
  "resultado": "REQUIERE_AUTORIZACION",
  "mensaje": "Requiere autorización de salida",
  "estado": "EntradaRegistrada",
  "idRegistro": "1_2026-10-04",
  "idAutorizacion": null,
  "nombreAlumno": "Manuel Damian Guinto Méndez"
}

Response - salida autorizada

{
  "resultado": "SALIDA_AUTORIZADA",
  "mensaje": "Registro de salida exitosa, buen regreso a casa",
  "estado": "SalidaAutorizada",
  "idRegistro": "1_2026-10-04",
  "idAutorizacion": "AUT-A1B2C3D4",
  "nombreAlumno": "Manuel Damian Guinto Méndez"
}

Response - salida normal

{
  "resultado": "SALIDA_REGISTRADA",
  "mensaje": "Registro de salida exitosa, buen regreso a casa",
  "estado": "SalidaRegistrada",
  "idRegistro": "1_2026-10-04",
  "idAutorizacion": null,
  "nombreAlumno": "Manuel Damian Guinto Méndez"
}
Mensaje esperado en LCD:
Si no puede salir: Requiere autorización de salida
Si la salida fue aceptada: Registro de salida exitosa, buen regreso a casa
POST /api/autorizaciones

Crear autorización de salida

Crea una autorización temporal para permitir la salida anticipada de un alumno o de todos los alumnos de un grupo. La autorización guarda quién autorizó, la hora de autorización y el motivo. Cuando posteriormente el alumno vuelva a poner su huella, el servicio de asistencia localizará esta autorización.

Request - autorización por alumno

{
  "tipo": "ALUMNO",
  "fingerprintId": 1,
  "idUsuarioAutoriza": "TMARTINEZ",
  "motivo": "Solicitud del tutor"
}

Response - autorización por alumno

{
  "idAutorizacion": "AUT-A1B2C3D4",
  "tipo": "ALUMNO",
  "fingerprintId": 1,
  "idGrupo": null,
  "idUsuarioAutoriza": "TMARTINEZ",
  "fechaHoraAutorizacion": "2026-10-04T20:15:30Z",
  "motivo": "Solicitud del tutor",
  "activa": true,
  "fecha": "2026-10-04"
}

Request - autorización por grupo

{
  "tipo": "GRUPO",
  "idGrupo": "3",
  "idUsuarioAutoriza": "TMARTINEZ",
  "motivo": "Salida anticipada del grupo"
}

Response - autorización por grupo

{
  "idAutorizacion": "AUT-E5F6G7H8",
  "tipo": "GRUPO",
  "fingerprintId": null,
  "idGrupo": "3",
  "idUsuarioAutoriza": "TMARTINEZ",
  "fechaHoraAutorizacion": "2026-10-04T20:20:00Z",
  "motivo": "Salida anticipada del grupo",
  "activa": true,
  "fecha": "2026-10-04"
}
El usuario que autoriza debe existir en usuariosSistema y estar activo.
POST /api/alumnos/importar

Importación masiva de alumnos

Recibe un archivo CSV mediante multipart/form-data y crea o actualiza documentos en la colección alumnos. El identificador del documento es el valor de idAlumno.

Request

Tipo: multipart/form-data

Nombre de la parte: file

POST /api/alumnos/importar

form-data:
file = alumnos.csv

Encabezados esperados del CSV

idAlumno,nombre,apellidoPaterno,apellidoMaterno,nombreCompleto,idGrupo,fingerprintId,codigoTutorHash,tutorNombre,tutorParentesco,tutorTelefono,tutorTelefonoAlternativo,tutorCorreo

Response

{
  "registrosImportados": 400
}
El servicio registra automáticamente activo = true, fechaRegistro y fechaActualizacion.
GET /api/alumnos/consulta

Consultar alumno e historial de asistencia

Permite consultar la información de asistencia del alumno. Si el código pertenece a un tutor, solo devuelve el alumno asociado a ese código. Si el código pertenece a un usuario de usuariosSistema, puede consultar todos los alumnos y opcionalmente filtrar por nombre.

Request - tutor

GET /api/alumnos/consulta?codigo=147896325

Request - usuario del sistema con filtro

GET /api/alumnos/consulta?codigo=SUPERCODIGO&nombre=Manuel

DELETE /api/registros/limpieza?dias=7

Limpieza de registros antiguos

Elimina de la colección registro los documentos cuya fecha de entrada sea anterior al número de días que se desea conservar. El valor predeterminado es 7 días si no se envía el parámetro.

Request

DELETE /api/registros/limpieza?dias=7

Response

{
  "eliminados": 128,
  "diasConservados": 7
}
Si no se especifica dias, el servicio utiliza 7.

Parámetro de negocio usado por la salida

La colección systemParams contiene el parámetro minutosToleranciaSalida. El backend lo consulta directamente en Firestore. Si el valor es 20 y el grupo tiene hora de salida 14:00, el alumno puede salir sin autorización desde las 13:40. 

{
  "minutosToleranciaSalida": 20
}
